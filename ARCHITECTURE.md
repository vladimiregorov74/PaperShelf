# PaperShelf Architecture

## Цель проекта

PaperShelf --- настольное приложение на Python 3.12 + PySide6 для
сохранения, организации и чтения технических статей (в первую очередь
Habr).

## Основные принципы

-   Production-подход.
-   SOLID (в первую очередь SRP).
-   Минимальная связность.
-   Явные зависимости.
-   Type hints во всех публичных API.
-   Docstring для классов и методов.
-   Без «магии».
-   Логика выносится из UI в контроллеры и сервисы.

## Слои проекта

### ui/

Отвечает только за отображение интерфейса и получение действий
пользователя.

### controllers/

Координируют сценарии работы пользователя. Не содержат бизнес-логики.

### services/

Бизнес-логика приложения.

### workers/

Фоновые операции (QThread).

### parsers/

Парсинг сайтов.

### models/

Модели данных.

### core/

Инфраструктура проекта. Сейчас используется `paths.py`.

## Направление зависимостей

UI → Controller → Service → Core

Нижние слои не должны зависеть от верхних.

## MainWindow

MainWindow должен оставаться максимально "тонким".

Не должен: - работать с потоками; - выполнять сохранение; - сортировать
библиотеку; - содержать бизнес-логику.

Допустимо: - создание компонентов; - делегирование вызовов контроллерам.

## Контроллеры

Каждый контроллер отвечает только за один сценарий.

-   SaveController
-   LibraryController
-   ArticleController

## Соглашения

-   Один класс --- одна ответственность.
-   Не оставлять TODO в основном коде.
-   Не создавать пустые заготовки файлов без необходимости.
-   Перед крупным рефакторингом сначала обсуждается архитектура.

## Цель развития

По мере роста проекта новые возможности должны добавляться через новые
сервисы и контроллеры, а не увеличивать MainWindow.

Я бы развивал проект в таком порядке:

Довести механизм регистрации новых сайтов до полностью рабочего состояния (сейчас мы почти у цели).
Добавить BrowserDownloader для поддержки JavaScript-сайтов вроде Notion.
Сделать окно "Поддерживаемые сайты" с возможностью:
просмотра списка сайтов;
удаления поддержки;
переанализа сайта;
проверки актуальности селекторов.

Это даст PaperShelf гораздо более зрелую архитектуру: приложение сможет само расширять список 
поддерживаемых сайтов и поддерживать его в актуальном состоянии без ручного редактирования selectors.py 
и site_registry_data.py.
